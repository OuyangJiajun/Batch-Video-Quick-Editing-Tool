# 视频剪裁工具

在播放视频的过程中随手标注若干「要保留」的片段，导出时只保留这些片段、其余全部删除。
**成片默认存回原视频所在文件夹，文件名 = 原文件名 + `_剪辑`**（例：`旅行.mp4` → `旅行_剪辑.mp4`），不会覆盖原片。

支持**打开整个文件夹**（递归所有子文件夹），一部接一部地剪；**标完一部直接切下一部，上一部在后台继续剪**，不用等。

绿色、免安装：本地 Python 起一个服务，用浏览器当播放器，ffmpeg 负责真正剪辑。

## 启动

### 准备

| 需要 | 说明 |
| --- | --- |
| Windows 10 / 11 | 文件选择框、回收站走的是 Win32 API，目前只支持 Windows |
| Python 3.9+ | 只用标准库，**不需要 pip install 任何东西** |
| ffmpeg | 把 `ffmpeg.exe` 放进 `bin/`（见 [bin/README.md](bin/README.md)），或者装到系统 PATH 里 |

### 启动

双击 **`启动.bat`**（或用命令行 `python app.py`），浏览器会自动打开操作界面。
关闭那个黑色命令行窗口即可退出。

首次启动如果 Windows 防火墙弹窗，选「允许」即可（只监听 127.0.0.1，不对外网开放）。

## 怎么用

### 剪一部片子

1. **打开**：点左上角「打开视频…」选单个文件，或「打开文件夹…」把整个文件夹递归列出来（也可以直接把视频拖进窗口）。
   打开后后台会自动给这部片子做「顺滑预览」（低清副本，跳转不卡），编好自己切过去，画面左下角会显示进度；
   **同时会顺手把后面两部的预览也编好**，一部接一部标的时候切过去是秒开（列表名字前面有绿色 ⚡ 表示已备好）。
   不想要就点「切回原画质」，之后这部片子不会再自动切。详见 [快进快退为什么卡](#快进快退为什么卡怎么解决)。
2. **边看边标**：
   - 在时间轴上**按住拖动**，直接框出一段 → 生成一个片段；
   - 或者播到位置按 <kbd>I</kbd> 打入点、再按 <kbd>O</kbd> 打出点，<kbd>Enter</kbd> 加入片段；
   - 加完后入点会自动接到这一段的结尾，可以一路「打点 → 打点 → 回车」连续标下去。
3. **微调**：右侧列表里可以直接改起止时间（格式 `mm:ss.mmm`，回车生效）；时间轴上拖片段本体可整体平移，拖两端可改边界；双击片段单独循环试听。
4. **导出**：点「导出保留片段」（或 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>）。

### 一次剪一整个文件夹（这次新增）

1. 点「打开文件夹…」→ 选中放视频的文件夹，程序递归扫描所有子文件夹，把视频列在左侧。
   - 已经导出的 `xxx_剪辑.mp4` 会自动排除，不会越扫越多；
   - 按文件名自然排序（`EP2` 在 `EP10` 前面）；
   - 顶部搜索框可以按文件名或子文件夹名过滤；
   - 每一行右边显示状态：`3 段`（标了没导）/ `已导出` / `62%`（后台正在剪）。
2. 剪完一部，按 <kbd>]</kbd>（或点「下一部 ›」）切到下一部：
   - 这一部的标注**自动进后台剪辑队列**，你不用等它；
   - 界面立刻可以操作下一部，播放、拖时间轴都不受影响；
   - 队列是串行跑的，前一部剪完自动剪下一部，界面左下「任务」页能看到每一部的进度。
3. 想一口气把标过的都导出来：点左侧底部的「导出全部已标注」。
4. 「切换视频时自动后台导出」这个勾（默认开）控制第 2 步的行为，不想自动就取消勾选。
5. **「剪辑完成后删除原视频」**（默认不勾）：勾上后每部片子剪辑成功就把原片删掉，适合整季剪完不想留双份素材。
   - 默认先进**回收站**，误删可以还原；回收站放不下的大文件才会直接删除。
   - 只删「剪辑成功、成片已落盘校验通过」的原片；导出失败、成片异常、原片正被别的程序独占时，一律保留原片，并在任务详情里写清原因。
   - 只对**勾选之后提交**的片子生效，不会追溯清理你之前导出的片子。
   - 删完那部会从左侧列表和标注里一起消失，按 <kbd>]</kbd> 会顺着它原来的位置继续往下。每次删除都会记在 `exports.log` 里（带 `[原片已删]` 标记）。

标注会实时存到本地文件 `_data/annotations.json`，关掉工具、换浏览器、清缓存都不会丢，下次打开还在。

## 两种裁剪方式

- **精确（默认）**：逐帧重编码，切割点和你标的时间点一致，画质几乎无损。只重编码你保留的部分，而且你在标注时它已经在后台编好了，所以点导出基本是瞬时的。
- **快速**：不重编码，直接复制码流，秒级出片。代价是切割点会往前对齐到最近的关键帧；程序会逐段校验偏差，超过阈值（短片段 0.5 秒、长片段最多 2 秒）的那一段会自动改用精确裁剪，并在完成信息里注明。

## 快进快退为什么卡，怎么解决

卡的根源不在软件，在**视频本身的关键帧间隔**。压缩视频不能随便跳——要显示第 40 秒的画面，
解码器必须先找到它前面那个关键帧（I 帧），然后把中间几百帧全解一遍。

用同一部 1080p/30fps、8.3 秒一个关键帧的片子量了四组目标，耗时几乎是条直线：

| 跳到目标前关键帧之后 | 要解多少帧 | 屏上出现画面 |
| --- | --- | --- |
| 0.1 秒 | 3 帧 | 15 ms |
| 4 秒 | 120 帧 | 180 ms |
| 8 秒（整段 GOP） | 240 帧 | 350 ms |

**一次跳转 ≈ 12 ms + 1.4 ms ×（目标离前面那个关键帧的帧数）**。所以「按住方向键卡住然后猛跳一下」
就是每次都要重解 250 帧，而你按得比它解得快。

### PotPlayer 为什么到处跳都不卡

不是它有什么黑科技，是三件事凑一起：

1. **它默认不精确跳转**。点进度条时它就近找一个关键帧停下，解码一帧就出画面；
   你看到的位置其实差一点，只是 0.5 秒的视频里没人察觉得到。浏览器必须落到你要的那一帧上。
2. **它的解码器是常驻的**，前后两次跳转复用同一个 GPU 解码器；
   浏览器每次 seek 都要把解码管线冲掉重建，固定开销就有十几毫秒。
3. **它没有中间的 HTTP 层**，直接 mmap 文件。（这一条对本工具影响很小：实测本地 Range 请求全程不到 10 ms。）

所以能抄的是第 1 条和第 2 条的目标——**让目标点前面没有东西要解**。

### 工具现在做了五件事

1. **顺滑预览默认就做**。打开任何一部片子，后台立刻排一个 720p、0.5 秒一个关键帧的副本
   （约 25 倍速，60 秒的片子 2~3 秒），编好自动切过去，不用点任何按钮。
   跳转从 **190ms 降到 5ms**，而且因为关键帧密，浏览器那个重建管线的固定开销也被摊掉了。
   不想用就点「切回原画质」，**这个选择会按文件记住**，以后打开这部不会再自动切回来。
   **导出始终使用原片**，画质不受影响。
2. **顺手预编后两部**。打开一部片子时，工具会把它**后面两部**的预览排到队尾一起编（不抢正在看的这部，
   也不影响导出）。一部接一部往下标的时候，切过去就是秒开——实测切到下一部：**打开 1~20ms，出画面 9ms**。
   列表里已经备好的片子，名字前面有个绿色 **⚡**。没扫文件夹、单文件打开时，按同文件夹的文件名顺序往后取。
3. **两段式跳转（抄 PotPlayer 的就近关键帧）**：在原画质下按方向键，先跳到目标前面那个关键帧
   ——那一帧十几毫秒就出来，时间码、游标同时到位，画面立刻有反应；70ms 后再精确补到真正的目标点。
   实测原画质下屏上出现画面 **350ms → 2~9ms**，同时最终落点仍然是精确的那一帧（不像 PotPlayer 会差一点）。
   顺滑预览本来就跳得够快，不做这一步。
4. **跳转合并**：连按方向键时，时间码和游标立刻跟着走，但真正让播放器跳的动作会等上一次跳完再发，
   中间那些被合并掉。实测连按 10 次原来只有 3 次能落地，现在只需解码 4 次就到位，不会互相打断。
5. **跳转中提示**：真要等解码超过 180ms 时，右上角会显示「跳转中…」，不用怀疑是不是死机了。

实测对比（同一部 1080p 长 GOP 素材，5 次远距离跳转）：

| | 原片（旧） | 原片（两段式） | 顺滑预览 |
| --- | --- | --- | --- |
| 屏上出现画面 | 190~350 ms | 2~9 ms | 5~20 ms |
| 最终落在精确那一帧 | 立刻 | +200~350 ms 后 | 立刻 |

顺滑预览副本存在 `_tmp/proxy/`，按文件指纹命名，**重开工具也不用重编**（上限 5GB / 10 天，超了自动淘汰）。

## 为什么导出这么快

以前的流程是「点导出 → 才开始一段段编码 → 拼起来」，你标注的那几百秒素材要从头编一遍。
现在改成**边标边编**：

1. 你按 <kbd>Enter</kbd> 加入片段（或在时间轴上拖出一段），约 1 秒后后台就开始把这一段编好、存进临时缓存；
2. 你继续标注、试听、调整的这段时间，后台把已有的片段一段段消化完；
3. 点导出时，编好的片段直接拿来拼接，只剩一次 `-c copy` 的封装，**通常 1 秒内出片**。

改动边界会让那一段的缓存作废重编，删片段会清掉对应缓存；缓存按「文件路径 + 大小 + 修改时间」分目录，多部片子各存各的，切视频不会互相清空。

面板上会实时显示进度：`后台预编码 2/5 段` → `5 段已预编码，点导出几乎立刻出片`。
如果某一段还在编你就点了导出，它会先等**这部片子自己**的段编完（已经在后台跑着，不会多花时间），再拼接。

**显卡加速**（默认开启）：用你机器上的 NVENC / QSV / AMF 做硬件编码，比 CPU 快约 1.5 倍。
码率上限按原片码率封顶，所以成片体积和原来基本一致；如果你的素材比较特殊导致体积异常，
把「显卡加速」勾掉就会退回 CPU 的 x264。切换时缓存会重建一次（有任务在跑时会先拦住，避免把正在用的缓存删掉）。

## 几个细节

- **不会覆盖原片**：成片名带 `_剪辑` 后缀，与原片天然区分。导出时先写成 `xxx_剪辑.part.mp4`，成功后才改成正式文件名，中途失败或断电不会留下半个可用文件被误用。
- **重复导出**：同一部片子重复导出会覆盖上一版 `xxx_剪辑`，方便反复调整。
- **同名撞车**：如果把多部片子都输出到同一个目录（比如不同子文件夹里各有 `01.mp4`），第二部会自动变成 `01_剪辑_2.mp4`，不会悄悄覆盖上一部。
- **容器格式**：尽量沿用原扩展名（mp4 / mov / mkv / ts / flv）。原片是 avi、webm、wmv、rmvb 这类不适合装 H.264 的格式时，成片自动输出为 `.mp4`。
- **播不了的格式**：HEVC / 10bit / 某些 MKV 浏览器解不了，界面会提示「正在生成顺滑预览」——编好自动切过去，
  导出时仍然用原始高清文件，画质不受影响。这和上面「顺滑预览」用的是同一套东西。
- **音轨**：原片有音轨就一起带上，没有音轨也能正常导出。
- **标注重叠**：新片段和旧片段重叠时，会自动切掉重叠部分，保证导出结果不重复。
- **缓存上限**：片段缓存默认最多占 20GB，超了就从最久没动过的片子开始清（正在剪的、正在导出的不动）。想改可以设环境变量 `CUTTER_CACHE_GB`。
- **顺滑预览缓存**：`_tmp/proxy/` 单独算，默认最多 5GB、保留 10 天，超了从最旧的开始删；原片被删掉时它的预览副本也一起删。

## 成片在哪？

导出成功后界面上会显示「完成（成片 xx 秒）→ 文件名」，鼠标悬停可看完整路径，
点「打开文件夹」直接在资源管理器里选中它。

另外每次导出都会追加一行记录到工具目录下的 `exports.log`（时间、原片 → 成片、时长），
以后记不清存哪了，打开这个文件搜一下就有。

## 常见问题

**导出的文件没有声音 / 画面卡住？**
先确认选的是「精确」模式；「快速」模式直接复制码流，遇到关键帧稀疏的素材现在会自动改精确裁剪，但如果仍发现首帧花屏，直接换精确模式即可。

**快进快退很卡？**
看画面左下角有没有「关键帧间隔 x.xs」的提示。有就点「生成顺滑预览」，跳转能从 190ms 降到 5ms；
没有提示说明这部片子本身关键帧够密，卡的可能是显卡解码跟不上（4K HEVC 常见），那就还是生成预览。
逐帧（<kbd>,</kbd> / <kbd>.</kbd>）检查切割点时，预览模式下同样快得多。

**导出后没看到文件？**
看界面底部那行完成提示，会写「成片时长 → 文件名」，文件就在「输出目录」那一行显示的文件夹里，点「打开文件夹」可以直接定位。

**后台在剪辑，会不会卡？**
不会。预编码单线程排队，CPU 限 4 线程、用显卡时几乎不占 CPU；后台导出和你在看的片子是分开的，实测一边后台剪辑一边播 1080p60 不掉帧。
导出任务本身也是串行的——排三个任务就一个接一个跑，不会三个 ffmpeg 一起抢磁盘。

**切走的片子会不会漏导？**
默认「切换视频时自动后台导出」是开着的：只要那部片子有标注、且标注在上次导出之后改过，切走时就会自动进队列。
真漏了也没关系，左侧列表底部「导出全部已标注」会把所有还欠着的片子一次提交。

**标注会丢吗？**
不会。每次改动都会存到 `_data/annotations.json`（浏览器本地还存了一份）。关工具、重启、换浏览器都能恢复。

**勾了「删除原视频」，万一剪坏了怎么办？**
原片默认是移到 Windows **回收站**，不是彻底删。发现成片不对，去回收站右键「还原」就回来了，文件会回到原来的位置。
只有回收站装不下的大文件（超过该磁盘的回收站配额）才会被直接删除，这种情况在任务详情里会写「原片已删除」而不是「已移入回收站」。
另外不建议把这条和「快速」模式一起用来做唯一一份素材的剪辑——先按精确模式确认成片正常，再批量删更稳。
只有你主动「清空」或删掉这个文件才会没。

**想按固定时间段批量剪一堆视频？**
现在支持整个文件夹一部部剪，但每一部的片段还是手标的。如果要「所有视频统一剪掉片头 30 秒」这种规则化批量，可以再做个命令行版本，需要的话说一声。

**能改 C++ 加速吗？**
换语言没用。这活儿的 95% 时间花在 ffmpeg 的解码/编码上，ffmpeg 本身已经是 C 写的汇编优化实现，外面套什么语言都一样。
真正能提速的是两件事：换硬件编码器（已做，+50%），以及把编码挪到你看片子的时间里（已做，感知提速 10 倍以上）。

**提示端口被占用？**
程序会自动往后找可用端口（8777 → 8778 …），以命令行窗口里打印的地址为准。
再双击一次 `启动.bat` 不会重复开，只会把已经开着的界面调出来。
